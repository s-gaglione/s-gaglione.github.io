Design note

Designers will design systems, not screens

A prompt now produces a credible landing page, a dashboard or a settings screen in seconds. That does not make designers obsolete. It changes what they are paid for.

By Sullivan Gaglione · November 2026

The screen is no longer the scarce thing

For most of the history of product design, a well-made screen was expensive. It took research, sketches, iterations, a pixel-precise mockup and a careful hand-off. AI tools have collapsed that cost. You can describe an interface and get a working, reasonably good version, often already in code.

When something becomes cheap, its value moves elsewhere. A decent screen is now a commodity. What is still scarce is knowing which screen to build, why, and how it fits with the forty others in the product.

From pixels to rules

The designers I see thriving spend less time drawing and more time writing rules: what a primary action looks like, when a table beats a list of cards, how errors are worded, how much density a power user tolerates. Those rules used to live in a designer’s head and in a style guide nobody read. Now they are the input that makes generated interfaces good instead of generic.

A design system was a library for engineers. It is becoming the brief for machines. The better it encodes intent — not just components, but when and why to use them — the better everything generated from it will be.

The sameness problem

There is a cost. Generated interfaces converge. The same rounded cards, the same gradient hero, the same three-column feature grid. When everyone can produce a competent screen, competent stops being a differentiator. Products start to look interchangeable, and users stop noticing them.

That makes taste more valuable, not less: the ability to say no to the default, to choose a typographic voice, to leave space where the template would fill it, to make one interaction feel considered. AI raises the floor. It does not raise the ceiling for you.

Prototypes become real

The most immediate change is speed of learning. A prototype used to be a picture of software. Now it can be software, built in an afternoon and put in front of users the same week. The bottleneck moves from making things to deciding what to test and reading what users actually do. Research and judgement become the long pole.

What I would tell a design team

  1. Write down your taste. Turn implicit preferences into explicit rules and examples. They are now your most reusable asset.
  2. Treat the design system as a product. Version it, document the “when”, not only the “what”, and measure how often generated screens break it.
  3. Spend the saved time on users. If screens are cheap, talk to more people and test more ideas.
  4. Protect a signature. Choose a few deliberate details that a default would never produce, and keep them.
